# 日记编辑器设计与扩展约定

本文说明旅行日记正文的数据模型、可视化编辑流程、图片版式语义以及新增区块时需要同步修改的位置。

## 设计目标

- 普通使用者不需要学习 Markdown，选择内容类型并填写表单即可完成日记。
- 会 Markdown 的使用者也不需要维护隐藏语法；正文始终是可预测、可校验的结构化数据。
- 编辑器、模板、公开页面和备份使用同一份正文，不维护兼容层或第二套事实源。
- 前端仍随 Spring Boot Jar 发布，不拆分独立前端工程，不增加 npm 构建步骤。

## 唯一正文协议

正文存储在 `journal_entry.content_json`：

~~~json
{
  "schemaVersion": 1,
  "blocks": [
    {
      "id": "block_m2abc123",
      "type": "paragraph",
      "version": 1,
      "title": "",
      "data": { "text": "从成都出发。" },
      "settings": { "style": "normal", "align": "left" }
    }
  ]
}
~~~

字段约定：

- `schemaVersion`：整篇文档协议版本，当前为 `1`。
- `id`：区块内唯一且稳定的标识。
- `type`：受白名单控制的区块类型。
- `version`：单个区块的数据版本，当前为 `1`。
- `title`：可选区块标题。
- `data`：业务内容；不同类型拥有不同字段。
- `settings`：受控外观设置，不接受任意 CSS、HTML 或 JavaScript。

数据库迁移 `V11__journal_block_document.sql` 会删除旧的 Markdown、模板填写数据、模板快照和脱离状态字段。该迁移面向尚未正式上线的开发阶段数据，不提供旧正文兼容转换。

## 内容块目录

当前提供 26 种内容块：

- 文字：正文、小标题、引用、提示卡片、信息清单、优缺点、表格、链接卡片。
- 记录：清单、评分、数字亮点、同行的人。
- 旅行：旅行信息、路线、行程、时间线、花费、地点卡片、美食、住宿、交通、天气。
- 图片：单张图片、图片组、旅行明信片。
- 排版：分隔线。

添加内容采用紧凑弹窗。选择类型后先填写完整表单，确认时才插入正文。区块列表中的图片仅作限高缩略展示，避免一张图片占满整个写作区域；完整效果在图片设置弹窗和公开页面中查看。

## 图片管理与插入

图片管理支持：

- 文件选择、拖放和剪贴板粘贴上传。
- 缩略图与放大预览。
- 单张或多选插入。
- 图注、设置封面、删除和批量删除。
- 按 EXIF 拍摄时间排序和拖拽手工排序。

从“添加内容”选择图片块，或从右侧图片管理点击插入，都会进入同一个图片设置弹窗，不存在两套图片配置逻辑。

### 图片设置分组

- 内容：选择图片、填写图注；明信片在这里填写地点、日期、寄语和署名。
- 版式：宽度、位置、图片组排版、列数和显示比例。
- 外观：相框、圆角、色调及电脑悬停效果。
- 图注：图注文字和显示位置。

预览区模拟文章正文纸张，并使用灰色文字线标识文字栏宽度。小图、中等、大图和正文宽度都相对文字栏计算；“通栏出血”表示图片向文字栏两侧延伸，但手机端会自动限制到可用屏幕宽度。

### 设置生效范围

界面只展示当前排版实际支持的设置：

- 左中右位置在“正文宽度”和“通栏出血”下没有意义，因此隐藏。
- 列数只适用于规则网格和瀑布流。
- 故事流、错落画廊和瀑布流保留照片原始比例，不显示裁切比例。
- 前后对比只渲染前两张图片。
- 电脑悬停效果不会在触摸设备上触发。
- 图注右置在手机端自动回到图片下方。

图片组模式包括规则网格、横向并排、瀑布流、主图拼贴、杂志版、故事流、错落画廊、轮播、胶片条和前后对比。胶片条在手机上原生滑动，在电脑上支持鼠标拖动和滚轮横向浏览。

## 移动端行为

- 日记内容与图片管理使用分段 Tab，不把两个长区域同时塞进一屏。
- 图片设置顶部预览固定，下方设置使用 Tab 独立滚动，修改后无需滚回顶部查看效果。
- 弹窗高度跟随 `visualViewport`，软键盘弹起后输入框会滚动到可视区域。
- 底部操作区只使用安全区补偿，不把键盘高度重复算作底部留白。
- 添加内容弹窗自身滚动，并为安全区留出尾部空间，避免浏览器菜单栏遮挡最后一行。

## 草稿与发布语义

- 草稿：支持服务器自动保存、“保存草稿”、预览链接和“发布日记”。
- 已发布：编辑时只把快照暂存在浏览器本机，不由定时自动保存直接改变公开文章。
- 点击“更新发布”后才提交已发布文章的修改；原始发布时间保持不变。
- 点击“撤回”后状态回到草稿，公开页面立即不可见。

## 扩展一个新区块

新增区块时至少同步以下位置：

1. `journal-blocks.js`：目录信息、默认数据、统一渲染和示例数据。
2. `journal-block-editor.js`：结构化填写表单。
3. `journal-blocks.css`：后台与公开端共用的展示样式。
4. `JournalDocumentService.java`：类型白名单、设置白名单、正文有效性和媒体引用提取。
5. 模板服务：如果新区块需要被日记模板生成，再增加模板输入与生成规则。
6. 自动化测试：覆盖合法文档、非法设置、发布时有效内容和媒体归属。

不要只在前端添加类型。后端校验与公开渲染缺失会造成保存失败或公开页面丢失内容。

## 本地验证

Windows PowerShell 使用项目指定的 JDK 21：

~~~powershell
$env:JAVA_HOME = "D:\java\environment\jdk21"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
mvn clean test
mvn clean package
~~~

前端不需要构建，但提交前应执行：

~~~powershell
node --check src/main/resources/static/js/common/journal-blocks.js
node --check src/main/resources/static/js/common/journal-block-editor.js
node --check src/main/resources/static/js/common/journal-media.js
node --check src/main/resources/static/js/admin-app.js
node --check src/main/resources/static/js/public-app.js
~~~
